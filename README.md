# Мини-апп для бота с заданиями
Телеграмм Бот https://t.me/only_low_code_solutions_bot
## Структура проекта

```text
cmd/bot/                  точка входа, загрузка конфигурации и сборка приложения
internal/app/             Telegram polling, HTTP API и фоновые напоминания
internal/config/          загрузка и проверка переменных окружения
internal/database/        подключение PostgreSQL и SQL-миграции
internal/domain/          доменные типы и правила
internal/handler/         HTTP-обработчики задач
internal/repository/      интерфейсы и PostgreSQL реализации
internal/service/         прикладные сценарии и валидация
internal/web/assets/      встроенные Mini App и website файлы
```

Docker собирает исполняемый файл из `./cmd/bot`. При запуске приложение
автоматически применяет миграции из `internal/database/migrations/`.

## Переменные окружения
| Переменная | Обязательна | Описание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | как раньше |
| `DATABASE_URL` | да | как раньше |
| `JWT_SECRET` | да | случайная строка не короче 32 символов |
| `BOT_TIMEZONE` | нет | как раньше |
| `MINI_APP_URL` | нет* | публичный HTTPS-адрес мини-аппа, например `https://homework.example.com` |
| `PORT` | нет | порт для веб-сервера, по умолчанию `8080` |
| `REDIS_URL` | нет | адрес Redis для rate limiting, по умолчанию `redis://localhost:6379/0` |
| `TRUST_PROXY_HEADERS` | нет | включайте только за доверенным reverse proxy, который перезаписывает `X-Real-IP` и `X-Forwarded-Proto` |
| `ADMIN_TELEGRAM_ID` | нет | числовой Telegram user ID администратора; без него управление контейнерами выключено |
| `COMPOSE_PROJECT_NAME` | нет | имя Compose-проекта, по умолчанию `todobot` |

Лимиты Redis защищают вход и регистрацию по IP/email, выпуск кода привязки по
IP/аккаунту и Telegram-команду `/link` по Telegram user ID. Счётчики временные;
при недоступности Redis эти операции отвечают `503`, остальные функции продолжают
работать.

Напоминания хранятся в журнале доставки. После ошибки Telegram бот повторяет
отправку с экспоненциальной задержкой до одного часа; старые записи при миграции
считаются уже отправленными.

*Без `MINI_APP_URL` бот продолжит работать как раньше (только текстом), просто без
кнопки. Задайте её, когда задеплоите и получите постоянный HTTPS-домен.

Для управления контейнерами установите `ADMIN_TELEGRAM_ID` в `.env`, затем
пересоздайте сервис командой `docker compose up -d`. Администратор открывает
личный чат с ботом и отправляет `/admin`. Кнопка перезапуска перезапускает все
контейнеры проекта; удаление требует отдельного подтверждения и удаляет
контейнеры проекта без удаления тома PostgreSQL. Для восстановления удалённых
контейнеров выполните на сервере `docker compose up -d`. Для этой функции сервису
бота нужен доступ к `/var/run/docker.sock`.

## Деплой
1. Разверните бинарник так, чтобы порт `PORT` был доступен снаружи по HTTPS
   (например, за Caddy/Nginx с TLS, или на платформе, которая сама даёт HTTPS-домен).
   Telegram Mini App **обязательно** требует HTTPS.
2. Пропишите `MINI_APP_URL=https://ваш-домен` и перезапустите бота — при старте он
   сам вызовет `setChatMenuButton`, домен в BotFather дополнительно регистрировать
   не нужно (это требуется только для прямых ссылок вида `t.me/bot?startapp=...`,
   которые здесь не используются).
3. Откройте бота в Telegram, нажмите `/start` или кнопку меню — откроется мини-апп.

## Известные ограничения / что стоит проверить
- Сборка проверяется командой `go build ./...` (или `go build ./cmd/bot`); SQL-миграции из `internal/database/migrations/` применяются ботом при
  старте.
- Мини-апп не дублирует напоминания — они по-прежнему шлются ботом в фоне
  (`reminderLoop`), это не зависит от того, открыт мини-апп или нет.
- В настройках мини-аппа можно выбрать интервалы за 14, 7, 3 и 1 день, а также
  добавить до восьми ежедневных времён напоминания. Дедлайн сегодня и просроченные
  задания напоминаются по выбранному расписанию. Команда `/remindtime ЧЧ:ММ`
  по-прежнему задаёт одно ежедневное время.
- В тех же настройках можно переключиться между текущим оформлением и неоновой
  темой из коммита `9a91c42`.

## Полноценный сайт и авторизация

- Главная страница сайта открывается по адресу `/`: регистрация и вход по email и паролю.
- После входа сайт открывает `/tasks` с тем же списком задач, календарём и настройками.
- `POST /api/auth/register` и `POST /api/auth/login` возвращают access JWT. Refresh-токен хранится в HttpOnly cookie, ротируется через `POST /api/auth/refresh` и отзывается через `POST /api/auth/logout`.
- Защищённые API принимают `Authorization: Bearer <access_token>`; Telegram Mini App продолжает передавать подписанный `X-Telegram-Init-Data`.
- При запуске автоматически применяются миграции `internal/database/migrations/012_website_auth.sql`–`014_invalidate_old_link_codes.sql`. Новым веб-аккаунтам выдаются отдельные ID до привязки Telegram.
- Для доступа к прежним Telegram-задачам войдите на сайт, откройте `/tasks`, нажмите значок связи в заголовке и отправьте боту `/link КОД`. После подтверждения веб-аккаунт использует существующий Telegram ID и видит старые задачи.
- Перед запуском задайте `JWT_SECRET` — случайное значение минимум из 32 символов. Например, его можно сгенерировать командой `openssl rand -hex 32`. Также заполните остальные обязательные переменные в `.env`.
