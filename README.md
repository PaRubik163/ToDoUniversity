# Telegram-бот для заданий

Бот принимает задания, сохраняет их в PostgreSQL и каждый день напоминает о них за неделю до дедлайна. PostgreSQL и бот запускаются вместе в Docker; после перезагрузки сервера они стартуют сами, а данные сохраняются в постоянном Docker-томе `todo_bot_postgres_data`.

## Первый запуск

1. Создайте бота через [@BotFather](https://t.me/BotFather) и скопируйте токен.
2. Создайте файл с настройками:

   ```bash
   cp .env.example .env
   ```

3. Впишите токен в `.env` после `TELEGRAM_BOT_TOKEN=`.
4. Запустите весь проект:

   ```bash
   docker compose up -d --build
   ```

Проверить работу можно командой `docker compose logs -f bot`. Остановить сервисы, не затрагивая задания: `docker compose down`.

> Не используйте `docker compose down -v`: эта команда удаляет постоянный том вместе с базой данных.

## Команды бота

Отправьте сообщение:

```text
Предмет: Разработка безопасного ПО
Задание: Практическая 1
Дедлайн: 6 октября
```

Даты можно указывать как `6 октября`, `6 октября 2026`, `06.10.2026` или `2026-10-06`.

- `/list` — список заданий по важности: ближайший дедлайн выше.
- `/delete 12` — удалить выполненное задание №12. Номер указан в `/list`.
- `/help` — подсказка по формату.

## Как развивать проект

Схема БД управляется миграциями в папке `migrations`. Для нового изменения создайте следующий файл, например `002_add_notes.sql`; при следующем запуске бот применит его один раз и отметит в таблице `schema_migrations`. Уже применённые миграции не редактируйте.

Исходный код намеренно разделён по ответственностям: HTTP-обмен с Telegram, обработка команд, напоминания и миграции. По мере роста проекта их можно выносить из `main.go` в отдельные пакеты без изменения формата базы или Docker-запуска.
